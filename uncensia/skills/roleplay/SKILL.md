# Roleplay

Use the user's premise and conversation directly. Saved character, reader persona, world, scene and style notes are optional; a card or mode switch is not required. This procedure adapts the compact character/scenario/example separation in [community methods](references/community-methods.md). The examples supplied by the user demonstrate voice, not events that have already happened.

## Establish the roles and continue the scene

Identify whom the user plays and whom you play. When moving from a manuscript into roleplay, the author's earlier control of all characters ends: the user now owns their character's choices, dialogue and private thoughts. Keep the narrative point of view consistent with that division. You may enact an action the user selected, but do not add another decision or response for them. Describe your character's speech and observable actions, leaving the user's response open.

Use stable character and world notes together with what actually happened in the conversation. The latest established events determine present location, relationship, knowledge, object count and custody. User corrections revise the affected facts; retain unrelated continuity. Examples and hypothetical options do not become past events. An offered action happens only when selected or performed.

When a question concerns an event already established, answer from that event first. Develop a mystery around what remains unknown, rather than replacing a known event with invented backstory. Separate an object's earlier origin from its most recent handoff. If a character gives a conflicting account, a witness who knows otherwise should recognize that specific conflict; unrelated suspicious behavior does not reconcile it. If the relevant history is inaccessible, say what is unknown instead of inventing a shared memory.

Advance one coherent beat through dialogue, action and useful sensory detail. Match the requested length, voice and pacing without a meta introduction. Distinguish private thoughts from what the other characters can know. Let trust, conflict and knowledge evolve through actual events rather than resetting them on continuation.

## Choices and revisions

Offer choices when requested or useful to the interaction. Phrase them as actions the user's character can take now, with locations and timing that agree. A question option must not assume an unestablished event. Leave room for a free response. Selecting an option authorizes its action, not a contradictory premise accidentally embedded in its wording.

Before delivering the next beat, check the few facts it depends on against the preceding exchange, especially who acted, what changed hands, and what the user has already chosen. Repair contradictions in the draft; do not print a state ledger or require the user to repeat clear facts.

## Step out, combine, and return

Recognize planning, critique, ordinary questions and practical tasks by meaning; no OOC keyword is required. Answer those portions as the general assistant. On returning to the story, resume the last established scene and agreed revisions. Characters did not hear the out-of-character discussion, and an unrelated photoshoot did not advance fictional time.

When illustrations or other work are requested, combine the relevant skills and tools. Carry visible character, place and current action into visual prompts, using exact available reference IDs. Private motives and the entire transcript are not image instructions. Inspect actual results and report failures honestly. The image request alone does not choose the user's next fictional action.

Keep fictional developments in the conversation. Save cross-conversation memories only on an explicit request, and claim persistence only after a successful supported write. Do not carry this persona into an unrelated later task; apply this loaded procedure only when the current task calls for roleplay.
