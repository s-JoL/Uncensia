# Uncensia

一个面向自由创作、支持 NSFW 的自托管 AI 工作室。由用户掌握模型、提示词和数据，把对话、图片编辑、视频生成与连续创作技能放在同一空间。底层保留通用 agent 的能力，通过按需加载的技能服务于不同创作任务。

这一页描述用户能感知的产品。设计取舍见 [09-design-principles.md](09-design-principles.md)，实现细节见后面的技术文档。

## 默认就是通用助手

打开后直接输入需求，不必先决定自己正在“使用哪种玩法”。可以先讨论点子，再写正文，进入互动故事，要求配图，挑选一张继续修改，临时问一个普通问题，然后回到之前的工作。

用户说清楚目标，agent 自己识别、读取并组合适用技能。角色卡、场景笔记和固定参考都是可选资料；填表、开关和 `/skill` 命令不是开始任务的前提。临时角色和写作风格不应干扰普通问答。

## 用户可以做什么

| 能感知的能力 | 应有的体验 |
|---|---|
| 接入自己的模型 | 填入连接、选择模型即可使用；本地和云端都有入口，显式选择不会被偷偷换掉 |
| 通用交流与办事 | 问答、分析、检索、处理文件，以及通过已接入能力执行工作；不为了聊创作就自动生成 |
| 原生图片与视频 | 对话中创建、查看和修改作品，看到进行中、完成和失败；需要精调时打开创作台 |
| 引用已有资料 | 上传、搜索和复用文件与作品；能选准确版本，知道用了哪张图、哪份资料 |
| 连贯的多轮任务 | 保留目标、范围、人物与已经发生的事实；继续、局部修改、换方向与取消都可自然表达 |
| 长任务与恢复 | 侧栏和对话顶部查看任务；支持持续推进、指定时间和定期执行，关闭页面后继续，可暂停、取消和查看结果 |
| 可控的记忆 | 明确保存有用偏好和资料，能查看、修改、删除并追溯来源；虚构角色经历不自动成为用户记忆 |
| 经验与自身改进 | 授权后把验证过的经验整理成技能，保存带来源的研究资料；长期指令有修改记录和旧内容可恢复，程序修改区分验证与生效 |
| 手机和平板使用 | 方便输入、阅读、看图、选参考和继续任务，多设备看到同一份对话与结果 |

## 默认附带的创作需求

这些是可以在同一段对话中自然出现、彼此组合的需求，**不是五个模式或五个产品入口**。默认始终是通用 agent。

| 需求 | 用户怎样表达 |
|---|---|
| 角色扮演 | “我来演来访者，你来演店主，别替我决定行动。” |
| 小说与同人写作 | “先充分铺垫，再引出线索；只改第二段，保留前面的版本。” |
| 互动叙事 | “给我几个选择，我也可以自己说；选这个分支继续。” |
| 图文故事 | “把这一步配成三张连续插图，文字和画面对应。” |
| 人物与主题组图 | “保留这张的人物和衣服，做三个不同场景的照片。” |

这些能力也适用于普通创作。能力的加入和调整通过 skills 等扩展进行，产品不因它们变成专用 RP 或生图应用。

## 什么时候算做到了

不是“有按钮、有工具、能返回一张图”就完成。应按 [真实多轮验收](08-acceptance-patterns.md) 检查用户原先的目标：理解对、选对参考与操作、完成约定范围、结果可用、能继续工作。

用户因误解、漏做、错误执行而不断修改指令，是需要消除的返工；它不能被统计为一种热门玩法，也不能成为必须经历的成功步骤。图片和 UI 必须实际查看，模型自报质量不算验收。模型能力或提供方错误造成的限制也要按事实记录，不能通过静默换模型制造成功。

## 当前边界

个人自托管使用，共用一台服务上的对话、资料和作品。多人协作与公共托管不是当前目标。

**1.0 的发布界面是 Web。** iOS 按最新要求在 `uncensia/native-ios` 从头实现 SwiftUI 原生端，借鉴 Conduit 的流畅性机制，以 Web 全功能为最低验收标准，见 [原生重建规划](15-ios-native.md)。旧 Flutter 客户端及配套流程已移除。体验与性能要在真实 Apple 开发环境验收；Windows 上的接口检查不替代它，也不计入 1.0 承诺。

写作质量、长上下文召回、画面保真取决于所接模型。持续任务保存目标、助手进度和执行记录；恢复生成工作还需结合已有 job 与 `inspect_generations` 核对成品。任务不会替代模型对质量与完整性的判断。
