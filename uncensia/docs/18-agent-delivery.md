# Agent 工作能力升级：执行目标与验收

2026-09-12。沿用 [对比设计](17-comparative-design.md)，范围为后端和 WebUI。

目标是把日常资料、创作和编码工作做到可交付、可追溯、可继续。以 ChatGPT/Codex 的工作体验和 Agent SDK 的执行契约为参照；不宣称不同模型有相同内容质量，也不通过更换模型或扩大权限制造成功。

## 本次实施顺序

1. 资料和历史：分页、命中上下文、跨会话阅读引用、不可变长工具原件。
2. SDK 接入：MCP 的错误、资源/结构化结果和完整发现；逐模型请求的上下文证据。
3. 成果与反馈：实时记录、用户接受/退回、版本检查和可见能力目录。
4. 在上述契约通过后继续推进项目和作品组织；工具加载的默认策略由实测决定。

## 发布门槛

- 151 项资料可全部枚举；历史命中后的原文可按范围读，越界引用明确失败。
- 超长单行和多行工具输出重启后仍可读到尾部；短预览不会替代原件。
- MCP 失败保持失败；资源链接、内嵌资源、结构化结果可进入模型上下文；分页完整。
- 每次实际模型请求有独立证据，区分已装配工具与实际调用、图片引用与真实像素。
- 反馈和交付更新无须换会话；模型检查不等于用户接受，旧成果引用不被悄悄替换。
- 权限与模型选择保持原契约；类型、相关 audit、完整回归和 Web 构建通过。
- 使用隔离真实模型工作流验证读取、引用、继续工作；视觉质量和外部服务限制单列。

先补会失败的回归用例，再修改实现。生产数据不作测试夹具；实现、契约测试、真实效果、提交和部署分别记录。

## 执行记录

- 开始：基线 af56e1e，保留上一轮研究文档和无关 workspace/ 内容。
- 资料分页先复现缺少下一页的问题，再通过 151 项不重复枚举与新增文件不挤乱分页的测试。历史引用能读到跨会话原文，不能直接跨会话滥用 entry_id。
- 单行 80 KB 和多行中文工具输出保存原件，服务重启后逐字相等；不可编辑快照不会被普通上传去重复用。
- 复查发现单行原件仍可能被模型预览截断；新增失败回归后补字符窗口。真实 Pi + HTTP 测试提供方完成“90 KB 工具返回 → 保存原件 → 用 ID 找尾部 → 提供方收到完整尾部”的三次调用；HTTP 分页可重新拼出整条单行，emoji 边界不被拆开。
- MCP 用真正启动的 stdio/HTTP 服务验证两页发现、失败抛出、资源链接后继续读原文。资源模板与二进制文件也走原连接。
- 交付 revision 与用户 review 分开持久化。文本冻结、重复调用不增版、旧版内容不变、过期验收返回冲突均有回归。
- 请求哈希与测试提供方实际收到的四次请求逐个相等；图片统计覆盖 OpenAI、Anthropic、Google 的请求形状。Web 显示的是请求准备证据，不能据此声称模型理解了图片。
- 隔离真实 GLM 5.3 Flash 工作流：第一轮 4 次模型请求完成跨会话原文摘录、90 KB 记录尾部识别码 amber-27、红色圆形/蓝色矩形视觉检查和 chapter-1 交付。第二轮 3 次请求按反馈改为最后一句，保留第一版并产生第二版；旧的用户接受状态没有继承。原文逐字比对，不以 run.completed 单独判定成功。
- Web 实际操作：保存带 BLUE-41 的反馈、接受第一版、面板保持打开时自动出现第二版、查看两版、退回第二版。资料和原图均为隔离测试夹具；本次未重新评估写作质量或外部生图质量。
- 最终 review 补齐反馈闭环：Web 保存的消息反馈会在后续每次模型请求前刷新进入本会话上下文，不依赖模型先调用历史搜索，也不会升级为全局记忆；附件已知 ID 的遗漏正文统一直接使用 `read_resource`，不再多走一次语义搜索；MCP 读取并保存的二进制文档会确定性关联当前项目。
- Web 原件阅读实测翻到第 8 页看见 `ORIGINAL_END: amber-27`，末页下一页禁用，上一页返回第 7 页；逐页导航保持原件版本，不把截断预览当全文。
- 完整 `npm run audit` 通过；TypeScript、Web 构建、文档 schema 和本地化检查通过。实际 390 CSS px 下 document/scrollWidth 均为 390，成果对话框 clientWidth/scrollWidth 均为 357；浏览器没有 warning/error。已移除成果面板的第二层滚动，将成果前置、检查依据和请求明细折叠。

## 本批边界与后续门槛

首批解决资料可继续读取、SDK 返回契约、执行证据和成果版本验收；继续使用 Pi 单一运行框架。当前可在每次请求记录查看实际可用工具，没有增加另一套常驻工具目录。项目组织继续在下述第二批推进；交互提问、长进程预算/恢复、工具按需加载的对照实验仍按 [对比设计](17-comparative-design.md) 后续阶段推进。本批通过不等于已达到 ChatGPT/Codex 的全部能力或模型质量。

所有真实测试运行在独立 data 和 loopback 8096，生产库未迁移，生产进程未部署。提交、推送与部署状态以实际执行记录为准。

## 第二批：项目工作区与成果阅读

先验收再实现：项目保存说明、文件关联和会话；两个项目的默认目录、检索与自动上下文不能互相混入。普通会话默认使用未归属项目的资料，明确指定文件或个人范围搜索仍可跨项目引用。项目不是文件系统权限沙箱，已有会话历史不会因移动项目而重写。

回归覆盖空项目不会退回全库搜索、说明更新在下一次请求生效、并发修改冲突、分支继承归属、重启持久化、移除关联不删除原件。Web 验收创建和编辑项目、选择资料、启动项目会话、成果原文预览及版本比较；比较显示固定版本，避免模型再次复述。

第二批执行结果：

- 新增项目、会话归属和文件关联三张表；文件去重、上传、引用、生成和导入均保留原件身份。默认目录与检索按当前项目，未归属会话使用未分配资料；个人范围和精确文件 ID 仍可主动跨项目引用。没有新增常驻模型工具。
- `audit-projects` 从项目创建 404 的失败用例开始，覆盖 HTTP 校验、项目间默认范围、空范围、重复文件关联、冲突、会话移动更新、真实 Pi 请求中途刷新、分支与重启。
- 成果支持原文、图像/视频预览，文本 diff 使用已有依赖树中的 jsdiff（新增直接依赖）；固定版本哈希校验、大小与计算耗时上限明确。差异可还原只改第二段后的完整字节，保留其他段落、CRLF、emoji。媒体并排查看，PDF/DOCX 等当前仅展示提取文本，未实现版式预览或任意文档原位编辑。
- 隔离 GLM 5.3 Flash 两轮共 7 次请求：首轮读取蓝港项目笔记、逐字摘录最后两行并登记 harbor；Web 修改项目说明后，第二轮正确回答 BLUE-42 / 北海岸的新蓝港。此处验证项目使用与原文交付，不评估文学质量。
- 首轮模型额外走了一次片段搜索，再经目录读到原文。夹具手工建立 chunks 但未标记 indexed，导致空结果被描述为无可检索文件；修正夹具索引状态，并将产品文案改成检查索引/读原件。清理旧工具描述的“默认全库”用语，在文件目录中明确已知文件用 read_resource；尚未做足够模型样本证明调用次数稳定下降。
- Web 实际创建“界面验收项目”、关联公共资料、进入其新会话并确认归属；编辑蓝港说明、查看原件、比较两版文本和蓝/琥珀两张图片。旧版预览标明版号，接受/退回按钮指明实际操作版本。390 CSS px 下页面无横向溢出，成果对话框 clientWidth/scrollWidth 均 357；浏览器无 warning/error。
