# iOS 历史加载优化（2026-09-08）

这轮针对真实使用反馈中的启动等待、历史列表重复加载和旧会话模型恢复。上一轮流式交互通过不代表加载性能已经达标。

## 改动

- 首屏会话、历史列表并行读取；直接复用 bootstrap 中的模型目录，避免再请求 `/models`。恢复连接时显示连接状态，避免先闪出登录表单。
- 消息首屏与翻页使用 `limit=20`，此前为 60。服务端会向前补齐一轮，实际返回数可能超过 20；没有截断消息正文、引用或多媒体。
- 审批加载不再阻塞消息首屏。历史列表使用 30 条分页，30 秒内复用，支持主动刷新。
- 最近四个已结束会话缓存最多各 40 条消息。回看先显示缓存，再核对服务端更新时间；未变化时不下载消息页。运行中的会话仍按实时协议恢复。
- 模型选择跟随当前会话详情；过期请求不能覆盖新会话。新建会话发送捕获原始输入和附件，不等待刷新历史列表；切换会话与发送成功之间的状态竞争受到隔离。
- 历史入口改成左侧面板，按今天、昨天、过去 7 天、更早分组，高亮当前项，保留搜索、分页和删除入口。打开侧栏时隐藏底部标签栏。
- 已结束消息的 Markdown 解析采用有容量上限的缓存；工具引用不重复解析；思考增量与正文一起合并到约 80 ms 一次的 UI 更新。

## 清理与命名

- 当前源码、工程、应用名称均为 Uncensia。验收模拟器旧名改为 `Uncensia iPhone SE acceptance`。
- 删除指向已不存在的 `../luma/node_modules` 的失效链接，在 `uncensia/node_modules` 重建依赖。锁文件的旧镜像下载地址切换为官方 npm 注册表，版本及 integrity 保持不变。
- 删除两个 Finder `.DS_Store` 残留。当前工作区没有旧 Flutter 或旧 `luma/` 工程目录。
- 保留兼容旧数据库、登录键和 Windows Node 路径的迁移逻辑。它们仍有运行用途，不属于淘汰代码。
- Codex 保存的项目标签与工作区根目录仍为 Luma：当前工具没有项目重命名接口，且禁止操作 Codex 自身 UI。本轮没有通过移动目录使已保存的项目路径失效。

## 后续：快速滚动时图片加载引起的位置变化

固定媒体画框，图片、加载占位和失败重试具有相同尺寸；横竖图完整等比适配，必要时留边。仅运行中的尾部输出允许自动跟随，手指开始接触滚动区即取消待执行滚动。更早消息加载完成后按原消息 ID 定位，移除总内容估算高度差补偿；用户在等待期间继续滚动时不再强行恢复。

新增 `scripts/ios-scroll-fixture.py`：本机 127.0.0.1:18094，80 条带图消息、横竖图交替、图片延迟 8 秒，不访问或修改生产会话。启动后，为 UI test runner 设置 `UNCENSIA_SCROLL_FIXTURE=1`，运行 `MediaScrollTests`。

iPhone 17 Pro 模拟器回归通过（25.308 秒）：快速上翻三次，取屏幕内可见文字作为阅读锚点，等待图片完成，前后位置差不超过 3 pt，返回最新按钮仍可用。最初使用部分被导航栏遮挡的整条消息的可访问范围误报了位移；截图中文字实际稳定，因此最终测试直接比较可见文字的位置。
