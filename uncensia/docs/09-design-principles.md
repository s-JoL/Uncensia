# 设计原则

1. **从普通对话开始。** RP、小说和组图是用户需求，通过按需技能组合完成，不为每种玩法增加独立引擎。
2. **复用成熟机制。** Pi 管理会话与工具循环，MCP 连接外部工具，标准技能保存工作流程。保留来源与许可证。
3. **代码负责确定性契约。** 校验模型、参数、资源 ID、权限、状态和取消；语义意图和下一步由 agent 理解，不用关键词猜测用户操作。
4. **尊重明确选择。** 不偷偷更换模型或改写用户参数，升级保留用户编辑过的提示词、技能和配置。
5. **资料可追溯、结果可继续。** 引用绑定版本，长输出保留原件，成果与用户验收分版保存，跨端使用同一状态。
6. **验证实际体验。** 编译、测试、真实内容质量与部署分别记录。文字需要阅读，图片与界面需要实际查看。

同一契约只维护一处。新复杂度应解决已存在的问题，避免增加掩盖错误的 fallback。性能优化需要保持权限更新、草稿、阅读位置、消息归属和资源身份。

多轮继续时保留用户未改变的约束；模型假设与技能建议不升级为用户要求。加载技能不等于永久进入角色，读取过的说明也不自动成为个人记忆。
