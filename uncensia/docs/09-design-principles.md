# 设计原则

产品目标见 [00-product.md](00-product.md)。以下六项以用户明确的取舍为准，用来审查实现，不以已经写出的代码反推原则。

1. **优先复用成熟成果。** 先看已有开源实现、成熟产品交互和社区 skills。复用其机制与经过实践的方法，保留来源和适用边界。小范围适配优于另起一套循环、UI 基础设施或导演提示词。当前使用 Pi 的会话与工具循环、标准 skills、MCP、Radix 交互基础组件。
2. **代码简洁，扩展清楚。** 同一契约只维护一处；复杂度应服务于已经存在的需求。一个新 skill、模型或服务不应要求重写聊天主流程。避免用大量 fallback 掩盖错误，也不为一个创作用例建立专用内核。
3. **默认通用 agent。** RP、小说、互动叙事、图文和主题组图是需求类型。Agent 理解当前目标后按需加载和组合能力；用户不必先选模式、角色卡或技能。读过一个 skill 不等于永久切换身份。
4. **语义选择交给 agent。** 意图、操作、参考用途和下一步由模型结合对话与工具能力决定。代码负责精确参数、资源 ID、状态、取消、限额和协议等确定性契约。不得用提示词关键词或正则猜测用户想生成、编辑、继续还是换后端；失败应明确呈现。
5. **用真实轨迹验效果。** 把历史中一个完整目标及其后续修改、引用、暂停和恢复串成多轮。先判原目标的首次交付，再分别记录主动新需求、被迫纠偏和恢复。代码检查负责执行事实；文字需要阅读，图片、视频与 UI 需要视觉验收。短样例、fixture 和模型自称成功不能替代真实完整任务。
6. **用户控制模型与创作。** 本地与云端 API 均可明确配置和选择，原有 writing system 段落按原文保留，用户自定义 prompt 不被升级覆盖。其他 prompt/skills 借鉴成熟经验，并以实际效果修订。不要用隐藏的后端替换或参数改写改变用户选择。

## 如何区分必要契约与替模型作决定

| 应在代码中确定 | 应由 agent 理解 |
|---|---|
| 图片 ID 是否存在、来源像素是否成功读取 | 哪张图是底图、哪张只提供人物身份 |
| 请求尺寸是否属于模型公布的可选值 | 当前画面应该选哪个可用尺寸 |
| 用户选定模型是否可用、实际使用的模型 ID | 未指定操作时，怎样满足新作品对原图身份的保留要求 |
| job 是否成功、已有资产和取消状态 | 哪个结果满足画面要求、哪些需要修订 |
| 会话或资料发生了实际变化，需要刷新 | 继续同一创作还是回答一个普通问题 |

Skill 按 Pi 的渐进加载方式进入会话：常驻的是目录摘要，正文在需要时读取，已读内容可用于后续相关任务。HTTP 一轮结束不是语义任务结束，不据此强制清空正文和要求每轮重读。历史读取保持原快照；压缩时不把可重新读取的程序正文提升为永久用户偏好，保留用户任务、事实和资产依据。是否退出角色由当前请求决定，不需要固定口令。

多轮执行先恢复当前目标、用户固定的约束、目标版本与未完成范围，再理解本轮改变了什么。用户未改的约束继续适用；模型自己的假设与 skill 的推荐不能升级为用户要求。新任务不继承无关约束。这一原则同时适用于文字格式、资料范围、媒体操作与后端选择，不以某类提示词关键词分流。方法参考 Anthropic 的[上下文工程指导](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)与[渐进加载 skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)：用少量明确原则组织上下文，不堆叠场景例外。是否改善必须由跨任务、多轮实测判断。

## 验收与证据

每项改变至少回答：它解决了哪个用户问题，复用了什么，是否引入语义规则，真实多轮是否改善，哪些仍未验证。记录入口见 [08-acceptance-patterns.md](08-acceptance-patterns.md)。代码已写、契约检查通过、真实效果通过、提交与部署是独立状态。

验收分开记录 **Uncensia 执行是否正确** 与 **所接模型的内容效果是否达标**。Uncensia 负责完整传递任务与所选上下文、准确接入和显示能力、传送像素与引用、执行并保存真实结果；写作质量、有效长上下文召回、视觉理解及生成编辑保真另列模型用例结果。先核对实际请求、文件和状态才能归因，不能把实现缺陷推给模型，也不要求靠特化规则弥补模型的一切能力不足。仍可用有来源的 skill、适当上下文组织与明确模型配置改善效果；未验证的提升不能计为通过。详见 [11-main-review.md](11-main-review.md)。
