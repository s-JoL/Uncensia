# Web 与 iOS

两个客户端共用 `/v1`、同一模型配置、会话树、媒体与任务。服务端拥有持久状态，客户端负责交互和展示。

## 界面入口

| 工作区 | Web | SwiftUI |
|---|---|---|
| 对话 | `/`、`/c/:id`，侧栏与阅读区 | 「对话」标签页，导航抽屉与输入区 |
| 创作台 | `/studio`，参数、队列与图库 | 「创作台」标签页，schema 表单、队列与作品 |
| 项目 | `/projects`，说明、资料与归属对话 | 「项目」标签页，列表与详情 |
| 资料库 | `/library`，文件、作品与记忆 | 「资料库」标签页，文件与作品 |
| 任务 | `/tasks`，另有聊天顶部任务面板 | 会话任务在对话内的后台任务面板，全局定时任务在设置 |
| 设置 | `/settings/…` | 「设置」标签页，分组导航 |

Web 侧栏在上述六个工作区间切换；iOS 用五个标签页（对话、创作台、项目、资料库、设置），任务与故事设定是对话内的功能、记忆归入设置。新用户的操作步骤见 [创作指南](guide.md)。iOS 构建与连接见 [iOS](15-ios-native.md)。

## Web 实现

`src/web/` 使用 React 19 与 Tailwind；Vite 输出 `dist/`，生产环境由 Node 服务静态文件。开发服务器端口为 3100，代理 `/v1` 到后端。

`api.ts` 管理鉴权和事件连接：令牌存在 `localStorage`（`uncensia.token`），服务端另设 HttpOnly cookie 让 `<img>` 直接取图，并通过 `x-uncensia-token` 响应头轮换令牌。SSE 由 `fetch` 读取（`EventSource` 无法带鉴权头），失败可回退长轮询，恢复按游标去重，回到前台时重连。可见且空闲的聊天页检查会话版本（`updatedAt` 与运行 ID）以接上另一端的运行和分支变化。URL 保存会话身份，草稿保存在当前标签的 `sessionStorage`。

`messages.ts` 组合消息和工具结果；正文已嵌入的媒体替代同轮独立副本。Markdown、引用与代码块由专门渲染组件处理。媒体查看器提供修改、参考、保存和来源。

创作台表单来自 `/studio/tools` 的 schema，提交走 `/jobs`。表单展示用户标题和可用参数，模型专用操作说明不直接作为界面文案。

## 原生实现

`native-ios/` 使用 SwiftUI，必要时通过 UIKit 与 QuickLook 提供文档、媒体和滚动行为。`APIClient` 统一网络、令牌轮换与认证，`RunFollower` 按游标增量恢复 SSE、失败回退轮询，`ChatStore` 管理会话和流式状态，已完成行与流式行分开更新。

项目、任务、成果与设置操作使用相同服务端契约；原生测试必须验证实际状态变化，不能只验证按钮存在。正文媒体去重以用户消息之间的一轮回复为范围，不隐藏下一轮重新使用的图片。

## 通用交互约定

- 模型选择、文件版本和图片用途保持明确。
- 加载失败提供错误与重试；已有内容不因刷新失败消失。
- 完成、失败和取消分别展示。
- 草稿不被后台刷新覆盖；旧请求不覆盖新筛选结果。
- 语言切换仅翻译界面，用户内容保留原文，见 [本地化](16-localization.md)。
