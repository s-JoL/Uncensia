# Agent

Uncensia 用 Pi 的 AgentSession 执行对话，SessionManager 保存原生会话树，DefaultResourceLoader 发现技能与扩展。依赖版本以 `package.json` 为准。Uncensia 负责请求、媒体引用、权限、应用状态和客户端展示，SDK 负责循环、工具调度、重试与压缩。

## 一次运行

`POST /v1/conversations/:id/runs` 创建 run。每个对话同时只运行一个任务；幂等键用于避免客户端重试重复提交。

1. 验证所选模型、附件、图片用途和编辑位置。失败在历史修改前返回。
2. 准备当前请求、可用工具、记忆和文件上下文。媒体持久化为准确的资源引用。
3. 创建 Pi 会话，发现有效技能；常驻目录摘要，正文由模型按需读取。
4. 执行模型与工具循环，必要时由 SDK 压缩。工具操作经过权限与审批。
5. SDK 保存会话树，Uncensia 将当前分支投影到 SQLite `messages`，持久事件经 SSE 送往客户端。
6. 等待工具、扩展与审批收尾，记录 completed、failed 或 cancelled。错误不冒充成功。

实现入口：`agent/runtime.ts` 编排产品运行，`agent/loop.ts` 对接 SDK，`agent/sessions.ts` 管理会话，`agent/projection.ts` 生成展示投影。SDK 宿主的完整边界见 [07-harness.md](07-harness.md)。

## 多轮控制

| 操作 | 契约 |
|---|---|
| 编辑 / 重试 | `fromSeq` 选择重写位置，旧分支仍保留；客户端整段重拉当前投影 |
| 分支 | 从指定节点创建独立对话，保留节点身份及对应配置 |
| 继续 | SDK prompt 写入明确的继续指令，指令和结果进入会话树 |
| 停止 | abort 传到模型、工具和审批等待，不把已完成结果删除 |
| 转向 | `steer` 在当前轮后插入用户文本，影响后续模型调用 |
| 回答后追问 | `followUp` 等当前回答自然结束，再处理用户文本 |
| 手动整理 | 创建可取消、可观察的 SDK 压缩 run，保留原始转写 |
| 后台任务 | 一次执行、持续推进或固定间隔执行；到期且对话空闲时走同一运行路径 |

转向和回答后追问需要活跃 run，否则返回 409。客户端恢复未被接受的草稿。队列文本进入原生会话并投影，重连后仍能解释回答为何改变。

关网页不会关闭服务端任务。服务重启后，未开始的任务继续等待；已经开始但被中断的任务标记失败，不自动重放可能有副作用的操作。主动停止当前 run 会暂停所属任务；用户可核对已有结果后继续。

任务通过 `create_task` 或聊天页顶部 / 侧栏的“任务”创建。普通对话提供 `list_tasks`、`control_task`，模型按用户意图安排和控制，不做关键词分流。任务轮提供作用域固定的 `report_task_progress`；保存总结、继续/完成/阻塞以及可选的工作量。进度数量是助手报告，界面不会把它伪装为服务器确认的质量。

持续任务每轮使用原目标、当前会话与保存进度，agent 决定下一步和是否完成。进度工具要求先交付本轮内容，再单独调用，通过 Pi 原生 `AgentToolResult.terminate` 结束工具批次，将后续轮交回调度器；不把这次正常交接标成取消。没有报告、报告阻塞或达到轮数上限时暂停，不以一次回复结束冒充目标完成。默认最多 10 轮，用户可明确选择不限；这是 run 数量，不是图片、token 或费用上限。

定期任务按固定间隔执行，至少一分钟，从指定开始时间计算后续时刻；忙碌或离线错过多个时刻只执行一次，之后跳过过期时刻，不集中补跑。不是日历 / 夏令时规则。调度最多同时运行四个不同对话，忙碌对话不会阻塞其他任务。同一对话仍只允许一个活跃 run。

“本轮后暂停”阻止后续轮次，让当前轮结束；“取消任务”同时请求停止对应 run。所有结果保留，执行记录通过 `runs.task_id` 追溯。暂停/取消优先于晚到的完成回写，结束回写幂等。旧数据库仅增加 `background_tasks.state` 和 `runs.task_id`，旧任务仍默认一次执行。

执行仍复用 [Pi AgentSession](https://github.com/earendil-works/pi/tree/main/packages/coding-agent)；调度状态与一次运行分离、暂停后续触发以及跳过过期时刻的取舍参考 [Temporal Schedules](https://docs.temporal.io/schedule)。这里只适配 SQLite 单机调度，没有引入 Temporal 服务或第二套 agent 引擎。回归入口：`scripts/audit-tasks.ts`。

## 上下文与历史

Pi 从当前分支的最新压缩点及后续条目构建上下文。Uncensia 在模型请求副本上处理以下契约，原始节点不改：

- 当前附件提供内容或像素；后续轮次保留文件、图片和视频 ID，需要时重新检索或查看。
- 工具结果限制单次体积，媒体按资源 ID 重载；历史保留与压缩完全交给 Pi，使用已保存模型的上下文窗口与输出预算，不在模型调用前另行丢弃旧轮次。
- provider、API、model 三者不匹配的旧 thinking 块不发给当前模型，避免被转换为助手正文。同模型思考及签名保留，工具 ID 和协议转换由 SDK 处理。
- 压缩输入保留引用身份与用途，省略可以重新读取的技能程序，避免将工具说明固化为用户偏好。

历史搜索、转写和导出各有用途：SQLite 是当前分支的展示/搜索投影，Pi JSONL 是原始会话树；导出树不等于导出全部媒体。

系统提示保留稳定身份、通用契约和 Pi 技能目录；时间、资料目录、附件正文和记忆放在模型请求副本中最近用户消息末尾的 `uncensia-current-context` 数据块。每次模型调用前重读记忆和资料目录，因此同一 run 内工具修改、删除或其他页面更正会在下一次调用生效。已发出的请求无法撤回；旧转写和压缩内容不会被修改。动态快照不持久化为用户消息，也不送入摘要成为长期事实。

记忆键名不再写入工具 schema。记忆/资料改变不修改 system 或 tools，但会改变最近用户消息的动态尾部；历史前缀仍可复用。提示词、技能目录、模型和工具配置在下一次 run 重建，变更后相应前缀缓存自然失效。具体命中率取决于提供方支持、路由、时间间隔和实际内容，不能用字节一致性测试声称已获得某个命中率。

## 技能与可选设定

技能读取使用 Pi 原生 `read`，目录由 SDK 发现并应用启停偏好。正文和 `contexts` 元数据解析复用 Pi。实际使用同一份发现快照包装读取、处理显式 `/skill:name`；上下文预算与压缩交给 Pi。

通用工具提示负责跨轮目标、明确约束、资源身份、依赖与结果证据；操作区别写在对应工具说明和 skill 中。继续优化继承先前明确选择，新的明确要求只改变相关部分。检查、讨论与执行分别理解，不靠关键词改写操作。官方来源与中性多轮验收入口见 [社区技能调研](community-skills.md)。

角色设定与视觉连续性由技能的 `contexts` 声明按需附加，不从用户文字猜测激活，也不常驻系统提示。角色设定包含人物、用户角色、世界、场景、风格与独立对白示例；视觉状态包含描述、固定参考和上一张成功图片。

读取结果是当时快照，后续 HTTP run 不自动清空已读正文，也不替换旧副本。模型根据当前目标决定继续角色、读取新设定或回答普通问题。技能开关影响下一次发现，不删除历史里已有内容。设置管理与外部技能限制见 [扩展能力](04-capabilities.md)。

## 权限与错误

工具按当前配置装配，固定顺序减少无意义的 prompt cache 变化。图片输入模型可获得 `view_image`，无需本对话先有图片。

Pi `bash`、删除/移动路径、覆盖已有文件的 `write` 等操作进入审批。超时或取消视为拒绝，结果明确返回；不依靠命令关键词黑名单决定语义意图。扩展错误、提供方错误、工具失败和用户取消分别保存，具体审批和工具范围以 `agent/approvals.ts` 与能力设置为准。
