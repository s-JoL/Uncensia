# iOS 原生重建

2026-09-07：用户调整技术路线，要求参考 Conduit 的流畅性设计，从头实现原生 iOS，功能完整覆盖 Uncensia Web 或更强。规划与集成由主代理负责，具体实现分派给 GPT-5.6 Sol 子代理。

## 目标与边界

新代码独立放在 `native-ios/`。SwiftUI 为界面主体，需要精确控制的系统媒体、文档及滚动行为可使用 UIKit。最低系统暂定 iOS 18，兼顾 iPhone 与 iPad。后端仍是 `/v1`，服务端拥有对话、运行、分支、文件与设置的唯一真相。

2026-09-08：按用户确认移除旧 `mobile/`、Flutter 专用脚本与 CI，只保留 Web 与 SwiftUI 原生端。不恢复已删除的旧 `ios/`，不改变本机 Node、ComfyUI 和业务数据。不将 Conduit 的账号体系、Open WebUI 业务、Android 或 Flutter 基础设施带入新端。若直接移植源码，必须保留相应授权与来源；仅借鉴设计也记录依据。

## 信息架构

- 对话：会话侧栏、阅读区、模型选择、附件与输入区；分支、设定和运行控制按需展开。
- 创作台：选择服务端操作、填写原生 schema 表单、跟踪任务、查看作品及来源。
- 资料库：文件和作品检索、上传与编辑、引用到对话；记忆可查看并管理来源。
- 设置：默认项、连接、模型、扩展、技能、工具权限、定时任务、个性化、访问与登录。

iPhone 使用原生导航与底部工作区切换；iPad 使用侧栏与详情。采用系统文字缩放、辅助功能标签、系统分享和文件选择。设置不得以整段 JSON 编辑器代替主要表单；技术结构只在用户需要查看原始详情时展示。

## 状态与性能设计

全局状态仅管理登录、bootstrap 和跨工作区导航。历史消息与正在输出的一行分别观察，避免每个 token 重建整页。消息使用服务端稳定 ID，历史分批加载；正文解析结果随消息版本缓存，长文本与媒体不得在 `body` 中反复解析或解码。

阅读锚点与自动跟随是不同状态：用户上翻后继续生成但不抢滚动位置；主动回到底部才恢复跟随。流式首帧及时显示，后续更新短间隔合批，输入区独立更新。连接恢复按事件游标去重，SSE 失败可回退轮询；前台恢复必须核对已存消息、活跃运行与审批。发送丢失响应时沿用幂等键，不重复创建运行。

令牌存 Keychain，草稿按服务器和会话隔离。请求错误保持可见并可重试；服务端空响应写操作算成功。鉴权媒体使用当前服务器的认证上下文，不将令牌传给任意外部 URL。

参考：[Apple 滚动几何 API](https://developer.apple.com/documentation/swiftui/view/onscrollgeometrychange(for:of:action:))、[SwiftUI 性能分析](https://developer.apple.com/documentation/Xcode/understanding-and-improving-swiftui-performance)。借鉴 Conduit 的稳定阅读锚点、增量显示与输入独立更新机制，效果由同设备实测判断。

## 实施与验收顺序

1. 统一网络和状态契约，建立独立可构建项目，三模块并行实现。
2. 对照 Web 操作检查写入字段、状态反馈与后续刷新；修复接口和集成缺陷。
3. 在独立空目录运行 `scripts/ios-ci-fixture.ts`，连接真实 Uncensia HTTP/runtime/SQLite；不使用生产资料。
4. Simulator 验证登录、会话闭环、工作区与设置导航，并逐页查看截图；协议测试覆盖失败与恢复。
5. 同一真机、同一长对话比较 Conduit 与原生 Release/Profile 的滚动、首帧、输入响应和内存。未测数值保持空白，不宣称更快。
6. 完整覆盖及真实体验通过后切换默认开发/CI 入口，再清理旧客户端。

可增强但不阻塞覆盖的方向包括 iPad 多栏、快捷键、系统分享入口、跨工作区精准引用。后台系统能力按实际授权和生命周期实现，不能承诺 iOS 无限后台连接。

## 开发入口

在 `uncensia/` 运行 `bash scripts/native-ios.sh prepare` 生成工程，随后用 Xcode 打开 `native-ios/Uncensia.xcodeproj` 的 `Uncensia` scheme。`bash scripts/native-ios.sh build` 构建 Simulator；`bash scripts/native-ios.sh test` 执行测试，可用 `UNCENSIA_IOS_DESTINATION` 指定设备。真实接口测试需显式设置 `UNCENSIA_IOS_FIXTURE=1`、`UNCENSIA_SERVER_URL` 和 `UNCENSIA_ACCESS_CODE`，并先启动独立测试后端。

### 体验验收脚本

| 场景 | 观察与通过条件 |
|---|---|
| 打开长会话 | 历史分批出现；滚动不会因每条消息重新解析而持续卡顿 |
| 正在输出时上翻 | 停在同一条消息的同一阅读位置；加载更早消息也不跳到段首 |
| 返回最新 | 用户主动操作后恢复跟随；输出期间键盘输入不丢字 |
| 网络中断与恢复 | 已显示内容不重复；最终结果与服务端一致；错误可以理解和重试 |
| 发送丢失响应 | 重试同一请求只产生一次运行；失败时草稿和附件仍在 |
| 后台再回来 | 读到服务端完成结果或真实活跃状态，并能处理审批 |
| 编辑与分支 | 编辑产生正确投影；另一个客户端切换分支后能同步，未保存设定不会被覆盖 |
| 资料到创作 | 原始文件版本和图片用途正确传递；完成作品可查看来源、重做并继续对话 |
| 管理配置 | 保存后从服务端重新读取值；错误不显示成功，冲突不覆盖新版本 |
| iPad 与辅助功能 | 三个工作区可用；大字体、横屏和键盘下主操作仍可见 |

性能对照需要固定相同设备、构建模式、历史内容和媒体缓存条件，记录首个可见增量、输入延迟、滚动卡顿和内存峰值。原生架构本身不构成“更流畅”的证据。
