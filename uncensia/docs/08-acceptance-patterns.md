# 测试与验收

在 `uncensia/` 使用 Node 24+：

```bash
npm run typecheck
npm run audit
npm run build
```

`typecheck` 编译类型；`audit` 在临时数据目录上用测试提供方和本地假后端配合真实 Pi SDK 成组检查协议、状态、存储、渲染、生成队列、鉴权与本地化；`build` 打包前端。它们都不证明外部模型的写作或图片质量。端到端验证 HTTP 契约用 `npm run e2e`：它对审计克隆实例发起真实请求并断言存储状态，无托管密钥时自动挂载本地 OpenAI 兼容桩，缺密钥的检查只跳过而不判失败。iOS 另运行 `bash scripts/native-ios.sh test`。

## 按受影响行为选择检查

| 改动 | 重点 |
|---|---|
| 会话与事件 | 发送、编辑重试、分支、取消、重连、跨端刷新 |
| 图片和 Markdown | 工具结果与正文只显示一次，代码示例保持字面，图文位置与预览正确 |
| 文件与项目 | 上传、分页、准确版本、原文范围、项目范围、再次引用 |
| 成果与反馈 | 冻结版本、修改产生新版本、用户接受/退回不串版 |
| 模型与工具 | 明确模型、参数、权限撤销、失败可见、凭证不外传 |
| 客户端 | 键盘、窄屏、长历史、延迟媒体、阅读位置、草稿和前台恢复 |

新增协议或修复缺陷时先建立能捕获问题的回归；低风险文档改动检查链接、命令和实现一致性即可。

## 真实创作验收

使用独立数据目录和端口，公开演示不得混入私人会话或凭据。例子见 [创作指南](guide.md)：导入小说 → 定位场景 → 三张插图 → 修改指定一张 → RP → 继续图文。

检查实际文本、生成数量、图片内容、引用版本及界面。记录模型、提示词、参数和输出；运行 completed 只证明执行结束。模型自报检查结果不能代替阅读和看图。

真实 API 调用可能计费，应限定任务范围；失败后先核对已提交 job，不盲目重发。演示素材和参数放在 [showcase](showcase/README.md)，本机日志、凭据和测试数据库留在 gitignored `run/`。
