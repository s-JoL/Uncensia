# 从真实使用记录验证产品

验收对象是通用 agent 帮用户完成真实目标的过程。工具调用成功、run 完成和结果符合要求是三个不同的判断，必须分别记录。五类创作需求按需识别与组合，不要求用户选择模式或填写角色卡。

2026-09-06 对当前生产数据做只读抽样：11 个对话、513 条投影消息、314 个生成任务。任务结果为 279 成功、33 失败、2 取消。历史记录包含连载、明确重新生成、多图来源、从记忆找图、角色互动与文件设定；测试使用新的虚构人物与场景，保留原任务的操作约束和连续性问题。

## 可重复的需求轨迹

| 模式 | 测试过程 | 通过标准 |
|---|---|---|
| 通用对话中的自然转换 | 讨论场景 → 写完整开场 → 进入 RP 并选择实际选项 → 三张图文 → 选合格版本做独立组图 → 两句话回答月相 → 回到故事 | 没有模式前置；当前目标控制所用能力；选图和角色事实正确；普通问题无需退出口令，无额外生图或剧情副作用 |
| 从描述到作品 | 新建对话，生成一个人物与带可辨识道具的场景，再检查图片 | 实际生成资产；眼睛看到的服装、道具、构图与要求匹配；不把提示词内容当作画面事实 |
| 局部编辑 | 只改风衣颜色或椅子颜色 | 使用原图编辑，来源 ID 正确；目视比较主体、场景和局部变化；披露分辨率变化或明显漂移 |
| 多图合成 | 上传次序与底图次序相反，指定底图和人物参考 | 底图始终为第一实际来源，参考图像素确实附带；模型和提供方保持明确选择；真实接口完成后再判断视觉效果 |
| 重新生成 | 已有角色参考，但用户明确要求独立生图 | 使用生成而非编辑；提示词携带可见外貌和场景；不声称仅靠文字能锁定相同人脸 |
| 有界连载 | 总目标 N，第一幕已完成；要求完成全部剩余；断线/恢复后再次要求完成约定数量；之后扩展到 N+2 | N=3 为冒烟，20 为完整任务，50/100 为长任务；恰好补齐缺项，建立序号到真实资产的对应；已完成时不重复，扩展只追加两项；失败尝试不计完成 |
| 跨对话视觉记忆 | 明确保存权威绿衣版本，另有较新的红衣图；在新对话询问原图细节 | 记忆保存准确版本 ID；新对话能读取该图像素；不会盲用最近图片；没有请求时不额外生图或写记忆 |
| 文件修订 | 资料库新建设定，加入对话；在界面修改暗号，再要求重新检索 | 当前正文和索引同步；文件范围正确；回答采用新暗号；空范围不能搜全库；索引失败可见 |
| RP 连续性 | 保存角色与旧场景；用户更新关系、地点与道具；选择分支；退出 RP | 新事件优先于旧设定；对白示例不当作历史；不代替用户决定；选项时空一致；普通问题不继续扮演 |
| 设置一致性 | 更改默认模型、刷新目录能力、保存并重新加载 | 只应用可审阅的草稿；保留自定义参数；不可用的显式选择报错，不暗中换模型 |
| 扩展与运行恢复 | 扩展启动、部分输出、通知、失败、取消与关闭服务 | 状态到达 Web；失败不显示为成功；关闭前等待在途工作和清理；恢复不丢失已保存结果 |

## 证据和测试层次

- 每轮先判断原始目标，再决定下一步。正常新方向、被迫纠偏和失败恢复分开记录；恢复成功不覆盖首次失败，正确输出不编造投诉。修改/纠偏的历史频率不能当作需求流行度。
- 轮次之间使用实际产生的回答、选项、资产和状态，不能预置助手回答或每轮另开空会话。分支明确保留分叉点和已经出现的事实；当前模型和提供方选择在测试开始前记录。

- 真实模型测试记录提示、run、工具参数、任务与资产 ID，以及最终回答；不公开模型的内部推理。
- 生图效果必须打开实际图片并比较。记录成功保存与视觉验收分别通过与否；身份相似度是人工判断，不能冒充客观量化指标。
- HTTP/SDK fixture 检查异常、取消、关闭、索引边界等确定性契约。它们不能证明真实提供方兼容性或图像质量。
- Web 操作检查入口、保存、刷新、搜索、草稿、图像预览和来源。只渲染一个按钮不算操作通过。
- 修改 prompt/skill 后重启隔离实例，确认实际采用新版，再重跑失败模式。不得改写生产历史来制造通过结果。

本轮真实模型及图片证据保存在 `run/history-live-20260906/`，正式数据目录保持独立。通过三幕用例不代表 50/100 幕的长时间执行、掉线恢复或长期人脸一致性已经验收；系列任务尚无独立持久化实体。

大范围重构的后续实测保存在 `run/product-refactor-20260906/`：逐轮 JSON 记录实际 run、工具和新增 job/资产；`progress.md` 记录当时通过与失败。M00 首次链中出现的身份漂移、道具数量、用户角色被代说和技能被提前清空均按缺陷保留。后续模型对照和修复重跑另用新前缀，不倒算基线成绩。代码检查通过与真实模型/视觉验收通过分开报告。

## 复用实际多轮用例

[`scripts/fixtures/product-history.json`](../scripts/fixtures/product-history.json) 保存来源定位、改编说明、逐轮用户输入和判断标准。脸部替换、重新生成后的优化、20 段图文使用代表性历史；体操组图保留成人历史里的复杂姿势、倒置、只出现同一人和可见脸部等难点，用完整运动服场景替代性描写。不能为了提高通过率删去难项。通用文件任务是补充回归，不冒充历史频率统计。

[`scripts/replay-history.ts`](../scripts/replay-history.ts) 通过真实 HTTP 执行一轮。明确设置 `UNCENSIA_EVAL_URL`、`UNCENSIA_EVAL_ACCESS_CODE`、`UNCENSIA_EVAL_MODEL` 后，从项目目录运行：

```sh
node --import tsx scripts/replay-history.ts story20 1 run/my-story-replay
node --import tsx scripts/replay-history.ts story20 2 run/my-story-replay
node --import tsx scripts/replay-history.ts story20 3 run/my-story-replay
```

它调用真实配置的模型和媒体服务，会产生实际用量。每轮沿用同一目录里的会话状态，前一轮的文字、工具与图片都来自真实执行。需要图片的用例先在该实例准备资源，在目录的 `bindings.json` 中填入 `base`、`face` 或 `reference` 对应的真实图片 ID。没有注入助手答案、替换生成工具或自动给视觉质量打勾。

`story20` 第4轮是根据真实产物补充的离线文件交付，第5轮保留本轮实际发现的编号/缩放缺陷及纠偏要求。它们有单独的 `origin`，不算原始历史输入；仅在上一轮确有相应排版缺陷时执行纠偏轮。新的首次交付如果已无此缺陷，应记录无需纠偏，不能先人为制造缺陷再计为修复成功。

记录包括实际模型、run、工具结果和分页读取的新增 jobs；推理正文与内联图片数据不导出，图片按资产 ID 在实例内查看。退出码只表示运行结束状态。完成一轮后，仍需按 `criteria` 读回答、核对源图/结果和检查 UI。观察超时保留任务，重复同一命令继续收集同一 run，不再次提交。若提交响应丢失，状态标明未知，先核对实例内记录，不能自动重试付费调用。执行失败、首次交付不合格和修复后通过分别记录。

当前重构的证据与未达标项见 [10-refactor-validation.md](10-refactor-validation.md)。
